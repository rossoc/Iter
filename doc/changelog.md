# Changelog

## Unreleased

### Added
- Instruction forms by field: the New instruction pop-up asks for name, description and prompt (a starter `develop` prompt); the Settings tab has a field each for name, set up like, description, model, mode, temperature, permission and prompt instead of one text area. Saving merges the fields into the file's front matter (`instruction::compose`), keeping keys the form does not know.
- Fixed: the New agent pop-up (and the agent page's Settings form) could be scrolled sideways: the hidden native `<select>` kept by the combobox was as wide as its field and absolute, so it stuck out of the box (`select.cb-native.control` in `combobox.css`); the prompt text area now wraps long lines.
- New instruction is a pop-up (`?new=instruction`, on `/instructions` and on the project's Instructions tab) instead of a panel above the table.
- Task Info: Plan is a section heading a level above Goal, How and Checkpoints (which share the small-caps label look); big-step names under Checkpoints are small and muted, below the label in rank; more space between `New session…` and `No sessions yet.`.
- An agent's page: the facts and buttons in a box on the right; tabs Prompt and Output (both rendered as markdown, Output with a raw view) and Settings only while the agent waits; the default tab is Prompt for a waiting agent and Output once it has begun.
- One look for every list of choices (`ui/combobox.js`): selects become a button and a styled list, text fields with suggestions filter as you type, the first match is highlighted and Enter picks it; native controls remain without script.
- An agent starting on a task makes it work in progress (`solve::begin`). The Agents tab's plan rail lists only the big steps (no summary line); the Info tab's plan shows the checkpoints, checked when done. The Agents icon is a person.
- New agent pop-up: no "Load prompt" button; picking an instruction fetches its prompt (`GET /task/{id}/prompt?instruction=`) and fills the text area, unless the prompt was edited since it was loaded.
- The Settings tab (the edit form) of organizations, projects and tasks shows the same count badges as their pages. Boards lose their Edit button too: Settings is the last tab of the agenda, matrix and info pages and of the board's edit form (`board_header::board_tabs`).
- Instruction pages: the list shows the description to the right of the name (on hover) and only the count of uses (no From column, no last use); the Agents tab has no Began column; the Edit button is a last **Settings** tab (`?tab=settings`) that holds the form, and Info is read-only.
- **Agents** in the top bar (`/agents`, a robot icon): every agent of every task; each agent has its own page `/agent/{task}/{n}` (Info and Settings tabs, Stop / Run now / Remove). The task's Agents tab links to those pages instead of opening an agent inline.
- New agent pop-up: Instruction and Model are text fields with suggestions (datalist); Queue only writes the agent down, nothing starts until Run now (the auto-start of queued agents is gone).
- Organization page: a **Projects** tab (count badge) holds the project list; Info keeps the description and settings. Organization, project and task pages have **Settings** as their last tab instead of an Edit button; the edit form is shown under the page's header and tab row (`edit_page`'s `sections`, `sections::settings_tab`).
- Instructions: the edit form changes the name (`instruction::rename_target`; built-in ones keep theirs); on the lists the description shows on hover only.
- Built-in instructions are now `plan`, `develop`, `test`, `check` and `fix` (`execute` and `investigate` are accepted as old names). The plan can have big steps (`### name` under its Checklist) with their own progress bar in the Agents tab's rail; the plan prompt asks for them. The New agent form offers only `plan` until the task has a plan, then every instruction that applies, including those in the task's own `instructions/` folder. New agent… is a pop-up; the tab is called Agents and carries the count; the plan (one per task, no counter) is under the description on Info.
- **Instructions** replace the project's Prompts: `instructions/<name>.md` files in opencode's agent format (`description`, `model`, `mode`, `temperature`, `permission`, and iter's `kind`), layered project > organization > iter's config folder > the four built in (`agent::instruction`). Pages: `/instructions` (global list, New instruction), `/instruction/{name}` with Info (view, edit, use the inherited one) and Agents (the runs given it), and a project tab Instructions; "Instructions" in the top bar. Runs record their `instruction`; the New agent form offers all that apply. (The folder was `prompts/`; the name is `instructions/` now.)
- Task page: **Notes** is a tab of its own, sketches moved to the Wiki tab; the agents table has the tasks table's look (model and effort show on hover, no start column); the Sessions table has hover highlight and a "New session…" row (`POST /task/{id}/sessions`).
- Agent tab redesigned: the plan's steps are a contents list on the left (a bar per step); the agents are a table at the top (what it does, state, run/stop buttons), **New agent** opens a form with the kind of work, agent, model and effort (lists: `agent.models` in `iter.yaml`, else the harness's own, and the server refuses others) and the prompt, filled for the task and editable; **Run now** or **Queue**. A waiting agent can be edited or removed; a working one can be opened (its output, what it was told) and stopped. New run states `queued` and `cancelled` (`commands::solve::{create, amend, begin, cancel}`). `{{worktree}}` stays in a prompt until its run begins. `POST /task/{id}/runs[...]` replaces `POST /task/{id}/solve`; the "Prompts for an agent" panel is gone.
- Sections that follow each other (`labelled_section`) are spaced by one rule, `.labelled+.labelled` in `ui/labelled.css`.
- Task page tabs: Info / Sessions / Agent (`?tab=`, `sections::TaskSection`). Agent shows the task's plan (goal, how, checklist with the state of every step and a progress bar), a step opened over the agents (`?tab=agent&step=s3`, buttons `POST /task/{id}/plan/{step}` to move it between todo, doing and done), and the notes and sketches in the task's folder. Doc: `doc/web_agent.md`.
- The task's folder: `<notes>/tasks/<id>/` with `plan.md`, `notes/` and `sketches/` (`agent::taskdir`, `notes::task_dir`). It lives with the notes, not in the worktree, so discarding a branch keeps the plan.
- The plan (`agent::plan`): `## Goal`, `## How`, `## Checklist` of `- [ ] {s1} (verify) text`; `[~]` is in progress. Reading is forgiving; ticking a step edits one character. CLI: `iter task plan <task>` (the editor; `--stdin` replaces, `--show` prints, `--mark s3 done` ticks a step; steps get ids; the previous plan is kept as `plan.prev.md`).
- `iter task prompt [-k plan|execute|fix|investigate] [--template F] [--no-onboarding]`: the prompt for an agent, filled from the task, its plan and what the wiki knows about it. Templates can be overridden per task, project, organization or in iter's config folder in `instructions/<kind>.md`; an unknown `{{placeholder}}` is an error.
- The wiki (`src/wiki/`): the notes seen as an RDF graph built in memory on every call (oxigraph, SPARQL), with an OWL ontology (`ontology.ttl`; a project or organization may extend it with `wiki/ontology.ttl`) whose classes say which folder they live in. `iter wiki find|grep|show|neighbors|check|mv|sparql|export|schema`; `--task|--project|--org [--down]` and `--format text|yaml|json` everywhere. `check` enforces the ontology, enumerations included (`confidence`).
- `iter notes today|list|show`.
- `iter task solve [task] [-k execute|fix|investigate|plan] [--agent claude] [--model M] [--effort E] [-y] [--wait] [-- harness args]`: hands the task to a headless agent. The editor opens first (front matter `agent`, `model`, `effort`; the body is the description the agent is given); `-y` skips it. The agent works in the task's worktree (made on the first run with the branch, reused after, no tmux and no timer; none when the project does not use branches) and runs detached unless `--wait`. Each run is `tasks/<id>/runs/<n>.yaml` (status, times, exit code, branch, pid), `<n>.prompt.md` and `<n>.log` (`agent::run`). `iter task runs [task] [--log N]` lists them or prints a log. `iter task done` still discards the worktree, or `--save` merges it. The harness is `agent::run::Harness` (Claude: `claude -p`, `--model`, `--permission-mode acceptEdits`; `effort` is told to the agent in its prompt).
- `iter wiki ingest [-p PROJECT | -t TASK] [--dry-run] [--detach] [--agent A] [--model M] [-- args]`: an agent turns the notes that no page has been made from since they changed (`check`'s dirty notes) into Idea pages; with `-t`, the task's sketches too. It runs in the notes folder with the prompt `wiki/prompts/ingest.md` (the rules come from `iter wiki schema`), its log in `.iter/`, and its changes are left uncommitted: `iter wiki pending` shows the diff, `--accept` commits `wiki/`, `--revert` throws away every uncommitted change under `wiki/`. The notes folder must be in a git repository. `iter wiki build-concept --name N <ideas...>` has an agent write a Concept that `include`s the ideas.
- `wiki/settings.yaml` (project, else its organization): `ingest: manual | on_task_start | on_task_done` (default manual). On task start (`session new`, the first `task solve`) or `task done` iter starts a detached ingest if the setting says so. It is kept in the wiki's own folder, not in the database, so the wiki stays self-contained.
- `iter task done` appends the task's own notes (`tasks/<id>/notes/*.md`) to today's note of the project under `## Task: <name>`, a `###` per file; once (a section with that heading is not added again).
- A task can be named by its number wherever a `<project>/<task>` is taken (`iter task plan 12 --mark s1 done`); the prompts use it, since a name with a space is fragile for an agent.
- A project with no notes folder keeps its task folders in iter's config directory (`tasks/<id>/`) instead of refusing: the Start button no longer ends in "not found". The Agent tab says so.
- `claude` gets `--effort`, `--add-dir <task folder>` and `--allowedTools` from `agent.allowed_tools` in `iter.yaml` (default: `iter task plan|prompt`, `iter wiki find|grep|show|neighbors|check|schema`, `iter notes`, and git status/diff/log/show/add/commit). Nobody can approve a command in a headless run, so add the project's test commands there (`Bash(pytest *)`); a hook that rewrites commands (`rtk`) needs `Bash(rtk *)`.
- Runs: one at a time per task (CLI and page); the record is `failed` whatever goes wrong on the way, and `lost` when its process is gone; the number is claimed with an exclusive create. `iter task done` refuses while a run is working. Only runs that change code (execute, fix) make a worktree and branch, before the prompt is written, so it names the right directory; a done task keeps its status. `iter session new` gives a headless workspace a tmux session instead of refusing.
- plan.md is written under a lock (`.plan.lock`) and through a file of its own per write: an agent ticking a step and a click on the page take turns. A trailing `(verify)` or `(verify: how)` marks a check; only the last parenthesis counts.
- The Wiki tab of the task page: pending pages as diffs with Accept / Throw away, the notes waiting to be ingested, and Ingest now (`POST /task/{id}/wiki/{accept|revert|ingest}`). `iter wiki pending` lists only `.md` pages under `wiki/` and acts on those files alone (not `settings.yaml` or `ontology.ttl`), works when the notes folder is inside a bigger repository, and clears staged pages on revert. One agent writes in a wiki at a time (`.iter/wiki.lock`, taken atomically).
- `wiki`: an empty `description:`/`updated:` is absent rather than an error; symlinks are not followed; `mv` rewrites `[[a/b.md]]`, refuses characters a path cannot have and a page moved out of the wiki's folders, and no longer loses text between matches; a note touched in the same second as an ingest is no longer dirty forever.
- The Agent tab lists the runs (latest ten, with the end of each log) and has a form that hands the task to an agent: what to do, agent (the harness picker; Claude for now), model, effort. `POST /task/{id}/solve` starts a detached run the same way `iter task solve -y` does (`commands::solve::start`) and goes back to the tab; one run at a time per task (400 otherwise); a task whose project has no notes folder is 404.

- A task's project can be changed: `project:` in the front matter of `iter task edit` (and in `iter task new`'s template), and a Project select on the task's edit page (`move_to`). Moving is refused while the task has a session (`IterError::TaskHasSession`); a name taken in the target project is refused as usual.

### Added (earlier)
- Search palette: `/` (or the bar's Search button) opens a Telescope-style box over any page: query on top, results on the left, and on the right the selected page in a frame, so it is interactive (inside the frame the bar, footer and palette are hidden). `kind words` restricts to a kind (`proj `, `task fix`, `org acme/proj web`), `is:wip|queue|done` finds tasks, a plain word matches titles first and descriptions second. Keys: arrows/Ctrl-N/P move, Enter opens (Shift/Ctrl/Cmd+Enter new tab), Tab completes a kind word then moves into the preview, Esc closes. The preview selects the first occurrence of the query's word in the page, as a drag of the mouse would. `GET /search?q=` returns the ranked JSON (`web/search.rs` ranks, pure and tested; `web/search_index.rs` reads the pages and notes); `ui/search.{rs,css,js}`. Doc: `doc/web_search.md`.
- Favicon: the site serves `src/web/favicon.ico` at `/favicon.ico` (`Asset::icon`) and links it from every page, the error pages included.
- Daily notes: organizations and projects have a Notes tab (`web/daily_notes.rs`, `ui/notes`): the notes by month, the latest day first, a "Today's note" button (`POST /{org,project}/{id}/notes/today`) and a page per day (`/{org,project}/{id}/notes/{yyyy-mm-dd}`) with the way to the previous and next day. A note is a file `YYYY-MM-DD.md` with `layout`, `title` (`dd/mm` by default) and the markdown body; reading is forgiving (`src/notes.rs`). Files are the only store.
- New `notes_path` setting on organizations and projects (edit forms, Info tab; `projects.notes_path` and `organizations.notes_path` columns). A project without one keeps its notes in a folder of its name inside its organization's.
- `iter internal restore` (for tmux-resurrect's `@resurrect-hook-post-restore-all`): after a reboot, recreates the tmux sessions of session-configs missing from the save, installs the hooks, closes clocks the previous tmux server left open at the last resurrect save (deletes them when there's no save after they started), and starts the clock of iter sessions a client is already on. New `tmux::server_start_time`, `tmux::last_resurrect_save`, `tmux::install_hooks_for_current_exe`, `clock::close_stale_session`.
- Agenda: the side column is now called Unscheduled, and has a fourth list, Backlog, for tasks neither urgent nor important; the list before it ("Urgent, not scheduled") holds the urgent, not important ones. Overdue and all three lists put urgent, then in-progress tasks first. The Matrix's Not placed column is renamed Backlog, folds into a rail too and lists in-progress tasks first.
- Agenda: the Not scheduled column is now called Backlog; its Important and Not important lists fold to their heading like Overdue.
- Agenda Backlog: the "Important" and "Not important" lists each collapse to their heading (`<details>`, open by default, no JS; `unplaced_list` `collapsible`).
- Agenda: the Backlog column (was Not scheduled) folds into a rail on its own edge (chevron to fold, rail to unfold, count and overdue dot, drop on it to unschedule). State is `?side=off` in the URL, server-rendered; replaces the toolbar button, its `localStorage` key and the script (`ui/side_rail`, `agenda_cards.rs`, `agenda_pick::with_side`).
- Task lists (org and project Tasks tabs): filter bar (`is:open` default, `is:done|wip|queue|all`, `tag:`, `project:`, `-` negation, free text, `#id`) in `src/web/task_query.rs`.
- Task lists: inline "new task" first row (`POST /task/quick`; org lists have a project select); returns to the same list.
- Org and board Info project lists: search box and create row (`POST /org/{id}/project/quick`, `POST /board/{id}/project/quick`; a board's project has no organization and is assigned to the board).
- Folder browser `GET /folders` (`src/web/folders.rs`) to pick a project path.
- Global footer on every page (`ui/site_footer`, `web/footer.rs`): organizations, projects, boards, GitHub link, version, link to Settings.
- Editable `/settings` page (`src/web/settings.rs`, nav bar item). `Config::save` writes `iter.yaml` (comments are lost); `config::replace` swaps the running config.
- Agenda: "Not scheduled" column toggle (remembered in `localStorage`); "Overdue" list for past open tasks, first in the column; big dashed "Schedule here" slot in pick mode; the day title opens a date picker.

### Changed
- The "+ New task…" and "+ New project…" first rows look hovered while no other row of their list is, so the way to add one stands out until the pointer picks another row.
- Descriptions (organization, project, task, board and the org report) are rendered as markdown, styled like the rest of the site. Raw HTML shows as text, only web, mail and relative links are kept, and headings sit under the page's own.
- Development: `.githooks/pre-commit` builds the test suite with `--features web` and with `--no-default-features` (`cargo test --no-run`) before each commit; enable it with `git config core.hooksPath .githooks` (documented in README, skip with `--no-verify`).
- Footer cost is bounded per page: it reads the first 8 projects of each organization, the first 8 loose projects and the first 8 boards (`footer::FOOTER_LIMIT`, three queries with window counts) instead of every project, and a longer list ends with a "N more…" link to its page. Before, every page listed the whole database in the footer.
- Build: topcoat is built with only `router`, `view` and `serve` (no compression, cookies, sessions, fonts, assets or route discovery), so about 120 fewer crates are compiled and a clean release build takes half as long (412 s to 207 s). `[profile.release] incremental = true`: a release rebuild after one change takes 2-27 s instead of 75 s.
- The stylesheet is linked once in `<head>` (no unstyled first paint) and `org.css` is bundled into it; `v2.css` is now `base.css`, served at `/style.css`, and the `.v2` scoping class is gone (the frame wrapper is `.page`, tokens sit on `:root`, text styles on `body`).
- Web: the duplicated page and form scaffolding is shared. `ui::form::form_shell` wraps every form (edit pages, Settings, New task, New project). `board_page::board_screen` wraps the agenda and the matrix. `panel` takes a `Row` list. `button::add_link` is the "+ New…" row. `ui/layout.rs` holds the layout atoms and `ui/table.rs` the table cells. `board_empty`, `form_actions`, `add_button` and five layout files are gone, and `NO_PROJECTS` moved to `web/text.rs`. The rendered HTML is unchanged; `/v2.css` only moves the layout rules together.
- Tests: the shared `src/fixtures.rs` (`db`, `project`, `add_project`, `board`) replaces the per-module copies. `agenda_pick`'s tests import `with_side` again, so they compile.
- Task and project lists: the first row is a link ("+ New task…" / "+ New project…") that opens a pop-up over the blurred page with the whole create form (task: project on org lists, description, status, tags, schedule, GitHub; project: description, base path, settings). No JavaScript: the pop-up is `?new=task|project` rendered by the server, the page behind is `inert`, and closing is a link (✕, Cancel, the backdrop). New component `ui/modal`; `frame` takes `dialog`.
- `POST /task/new` replaces `POST /task/quick`; `GET /project/{id}/task/new` redirects to the pop-up (the full-page New task form and the "New task" button are removed). The inline project create row is removed.
- New project pop-up: the base path and a "Choose…" button share one line. Choose posts the pop-up to `POST /folders/pick`, which opens the system's own folder picker (`osascript` `choose folder` on macOS, `zenity` elsewhere; `src/web/folder_picker.rs`) at the typed path (nearest existing folder) or the home folder, and shows the pop-up again with the chosen folder (and its name, when none was typed); everything else typed is kept. Without a picker it falls back to the folder browser (`/folders`), whose "Use this folder" returns to the pop-up instead of creating the project directly.
- Project lists (org/board Info, homepage cards): the path sits on the name's line, and a path too long for the row loses its start (`…/projects/iter-webapp`, CSS right-to-left box with the path isolated inside; the full path is the tooltip). It shows only when its row is hovered or holds focus (always on touch screens); its space stays reserved so nothing moves.
- Filter bar (one component, `ui/filter_bar`, on every list with a search: tasks and projects): the syntax is a "?" beside Filter; hover shows it, a click keeps it shown until a click elsewhere (CSS `:focus-within`, no script). The tip hangs from the bar's right edge and grows to the left, at most the bar's width, so it never leaves the screen. The project search now has a syntax too. The bar is at most 40rem wide.
- Task search: an empty box means no filter (every task, done ones too). The links into a Tasks tab (the tab, breadcrumbs, back links) carry `q=is:open`, so a list still opens on the open tasks; a list with no `q` is unfiltered (the server reads an empty `q=` as none). Clear empties the search. A query with no `is:` term matches every status.
- `Config`, `TaskDefaults` and `Settings` derive `Serialize`.
- Agenda cards are shared with the Matrix: no tags, duration or time; priority edge with hidden text; fixed 15rem width, several per row; Schedule link hover-only on big screens; no underline.
- Agenda hides tasks scheduled after today.

### Fixed
- The "+ New…" rows keep their text in the normal colour; only the background marks them while no other row is hovered, and the text turns blue on hover. "No tasks yet." under the tasks table is spaced and indented like a row. The page behind a pop-up no longer scrolls (`body:has(.modal-box[role=dialog])`).
- Form checkboxes sit centred on their label's first line (they sat a few pixels high: the input measured its own, smaller line height).
- Board (agenda and matrix): Schedule, Move, Place, Cancel and the pick-mode forms no longer jump the page to the card. The scroll position is saved before the action and restored on the same board and day (`board.js`); the card is still focused for the keyboard, and the `#card-<task>` fragment stays.
- Accessibility (review F1, F4, F12): task priority is a visible "Urgent"/"Important" chip in the card's meta line (`.tcard-prio`, was screen-reader text only; the edge stays as the redundant cue); inline `code` sets `--fg` in the one `code` rule (its per-component patches are gone); light `--accent` is `#3b5bd3` (4.70:1 on the accent tint, was 4.61).
- Pop-ups and the filter tip: a dialog's skip link is inert too, Esc closes a pop-up (`ui/modal.js`) and Tab stays in it (focus trap, footer inert); Esc closes the filter bar's "?" tip (`ui/filter_bar.js`, WCAG 1.4.13); a refused New task / New project pop-up says "Error:" in the page title.
- Agenda day field no longer reloads on every keystroke or arrow step: a typed or arrow-stepped date goes on Enter or when focus leaves the field, and only a complete date from 1970 counts (`board.js`, as the Report's range fields do); a picked date still goes at once.
- A malformed stored timestamp is a read error naming the value and column (`db::str_to_dt`, `Column` for `NaiveDateTime`) instead of a panic, so one bad row no longer turns every page that reads it into a 500. Unmatched URLs (`/nope`) get the styled "Not found" page: `error_pages` is a pathless layer (`LayerFn::new(None, ..)`), since a path layer never runs for a miss.
- Card border is visible after Cancel in pick mode (`.tcard:focus{outline:none}`).
