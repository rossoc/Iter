# Changelog

## Unreleased

### Added
- **Notifications in the web UI**: a toast in the top right corner, blue for a success and red for an error, that goes on its own after 5 seconds (paused while hovered or focused, with a close button). A saved form, a started run, a moved task and so on say so; a form refused with a 400/500 goes back to its page with the refusal as a red toast (same-origin `Referer` only; a script's `fetch` keeps the status); a form re-rendered with an error also raises it as a toast, beside the inline error box. New config key `notifications: { enabled, seconds }` (default on, 5), editable on `/settings` (seconds 1-60). Built from one router layer (`web/flash.rs`, a short-lived `iter_flash` cookie) and `ui/toast.{rs,js,css}`; `window.iterToast` is used by the board's drag and drop. The settings page's inline "Saved." notice shows only when toasts are off.

### Changed
- **Instructions live in the config folder, not in the binary.** `src/agent/prompts/` is now `instructions/` at the repo root; install it by copying it beside `iter.yaml` and `iter.db` (`cp -r instructions ~/.config/iter/`). The lookup is the task's folder, the project's notes, the organization's notes, then `<config>/instructions/`, with no built-in fallback: a name found nowhere is an error naming `<config>/instructions/<name>.md`. The web's instructions list shows only what those folders hold (an empty state when none), and any instruction can be renamed.
- **`-i/--instruction` replaces `-k/--kind`** on `iter task prompt` and `iter task solve`, and is required. Any instruction name works, not only the seven iter ships; `{{kind}}` is filled with the name.
- **Front matter `worktree: true` / `interactive: true` replace the kinds.** `worktree: true` (shipped on `develop`, `test`, `fix`) gives the run the task's branch and worktree; `interactive: true` (on `complete`) makes `solve`, `--subagent` and the web refuse it, pointing at `iter task prompt -i <name>`. `kind:` is no longer read. The `Kind` enum is gone.
- Run records store `instruction` (and `wants_worktree`); records that say `kind:` (also `execute`/`investigate`) still load and show their instruction's name.

### Added
- **Closing a task from `complete`**: after the sketch `result` (which now lists the task's commits under `## Commits`), the orchestrator asks the user: another round, edit the result, commit only, or conclude. Conclude commits in the worktree (`feat|fix|...: <subject>`), merges `{{branch.main}}` into the task branch and fixes what differs, merges the branch into main in the project folder (stops if that folder is not on main), lets a subagent ingest the task, commits the wiki as `update: <project>/<task> - <short sha of main>`, and asks whether to mark the task done.
- **Prompt kind `ingest`** (`iter task prompt -k ingest`, `iter task solve -k ingest --subagent`): a headless kind that changes no code and turns the task's sketches, notes and commits, plus the notes waiting, into wiki pages. Its template embeds the new placeholder `{{ingest}}`, the filled wiki ingest text ("(the project has no wiki)" without a notes folder; computed only when a template uses it). New placeholder `{{branch.main}}` is the project's default branch. The web still lists five built-in kinds.
- **The wiki ingest instruction is rewritten in the shape of a CLAUDE.md**: Purpose, Sources, Workflow (read fully; `iter wiki find` then update or create; cross-link both ways with `nb`/`ref`; flag `contradicts`/`supersedes`; `iter wiki check`; final report of pages created and updated), Rules. It reads only through `iter note read`, `iter note sketch|task list|read --task`, `iter wiki find|show|neighbors|check` and `git show --stat` for commits, and names no folder path: a task's sketches are `iter note sketch list --task <t>`. Shared by `iter wiki ingest` and the kind `ingest` (`ingest_prompt` takes the task instead of the sketches folder).
- `iter wiki pending --accept -m <message>` commits the accepted pages with that message (default `wiki: ingest`); `-m` without `--accept` is refused.
- **Orchestrated tasks**: the built-in prompt kind `complete` (`iter task prompt -k complete`) makes an interactive Claude session the orchestrator of a task. It writes the sketch `plan` (Requirements, Tests, Implementation) and a checklist, then runs rounds (at most 3) of test (TDD), develop and an independent check subagent, logs each round in the sketch `rounds`, and ends with the sketch `result`. `complete` is never a run: `iter task solve -k complete` is refused, and the web keeps offering the other five kinds.
- **Subagent runs**: `iter task solve -k <kind> --subagent` records a run without starting a process and prints its prompt for the session's own subagent. `iter task runs --close <n> --status done|failed|cancelled [-m report]` closes it, and the report becomes its log. Records carry `subagent: true` and are never shown `lost`. `iter task runs` gains an agent column, and the Agent tab marks these runs as subagents (`solve::prepare` is now shared by `begin` and `open_subagent`).
- The test, develop and check prompts read the sketch `plan` when there is one. Test writes failing tests first and records them in the sketch `test`. Develop makes them pass without weakening them. Check judges each requirement before reading the other sketches. Each ends with a short report.

A day under a quarter of an hour rounds to nothing and is not sent. The Report tab's *Copy summary* is now a *Share* button that opens a pop-up (Copy or Push, each with its own icon and button): copy (worklog or the old status list) or push to the organization's time platform, with the platform project and activity editable. `iter org push [name] [--date | --from --to] [--dry-run] [--force]` (today by default) sends one entry per day (`{"entries": [{project, activity, day, time, note}]}`, `time` in decimal hours, merged per day as in `info`: a pause of at most `pause_gap_minutes` counts as work; then each day is rounded to the nearest half hour, and a day that rounds to nothing is left out) as `POST <platform_url>/time-entries` (project and activity as the platform's ids, `date`, `time` in minutes) with a bearer key, via the `TimePlatform` trait and its `JsonWebhook`; a vendor adapter is a later implementation of the trait. Before pushing it asks the platform for the period (`GET <platform_url>/time-entries?from=&to=`, both days included): a day that already has an entry is a conflict, shown in red and not pushed, while the other days go through (the platform also answers per entry, `{"results": [{day, status, message}]}`). `GET <platform_url>/projects` and `GET <platform_url>/projects/{id}/activities` (`[{id, name}]`) turn the project and activity (a name or an id) into ids, warn about an unknown one, and suggest the choices in the organization's Settings tab and in the Share pop-up; the entries are read page by page (`has_more`). Results are reported per item; the `pushes` table is the ledger that refuses an identical second push (`--force` overrides), and a push during an open session is marked partial and fingerprints differently once it closes. The organization gains `platform_url`, `platform_project` and `platform_activity`; the API key is kept in the OS keychain (`iter org key`, read from stdin, `--clear` removes it) or `ITER_PLATFORM_KEY`, and never in the database, `iter.yaml`, a report, or an error message. ### Changed
- The "+ New task…" and "+ New project…" first rows look hovered while no other row of their list is, so the way to add one stands out until the pointer picks another row.
- Descriptions (organization, project, task, board and the org report) are rendered as markdown, styled like the rest of the site. Raw HTML shows as text, only web, mail and relative links are kept, and headings sit under the page's own.
- Development: `.githooks/pre-commit` builds the test suite with `--features web` and with `--no-default-features` (`cargo test --no-run`) before each commit; enable it with `git config core.hooksPath .githooks` (documented in README, skip with `--no-verify`).
- Footer cost is bounded per page: it reads the first 8 projects of each organization, the first 8 loose projects and the first 8 boards (`footer::FOOTER_LIMIT`, three queries with window counts) instead of every project, and a longer list ends with a "N more…" link to its page. Before, every page listed the whole database in the footer.
- Build: topcoat is built with only `router`, `view` and `serve` (no compression, cookies, sessions, fonts, assets or route discovery), so about 120 fewer crates are compiled and a clean release build takes half as long (412 s to 207 s). `[profile.release] incremental = true`: a release rebuild after one change takes 2-27 s instead of 75 s.
- The stylesheet is linked once in `<head>` (no unstyled first paint) and `org.css` is bundled into it; `v2.css` is now `base.css`, served at `/style.css`, and the `.v2` scoping class is gone (the frame wrapper is `.page`, tokens sit on `:root`, text styles on `body`).
- Web: the duplicated page and form scaffolding is shared. `ui::form::form_shell` wraps every form (edit pages, Settings, New task, New project). `board_page::board_screen` wraps the agenda and the matrix. `panel` takes a `Row` list. `button::add_link` is the "+ New…" row. `ui/layout.rs` holds the layout atoms and `ui/table.rs` the table cells. `board_empty`, `form_actions`, `add_button` and five layout files are gone, and `NO_PROJECTS` moved to `web/text.rs`. The rendered HTML is unchanged; `/v2.css` only moves the layout rules together.
- Tests: the shared `src/fixtures.rs` (`db`, `project`, `add_project`, `board`) replaces the per-module copies. `agenda_pick`'s tests import `with_side` again, so they compile.
- Task and project lists: the first row is a link ("+ New task…" / "+ New project…") that opens a pop-up over the blurred page with the whole create form (task: project on org lists, description, status, tags, schedule, GitHub; project: description, base path, settings). No JavaScript: the pop-up is `?new=task|project` rendered by the server, the page behind is `inert`, and closing is a link (✕, Cancel, the backdrop). New component `ui/modal`; `frame` takes `dialog`.
- `POST /task/new` replaces `POST /task/quick`; `GET /project/{id}/task/new` redirects to the pop-up (the full-page New task form and the "New task" button are removed). The inline project create row is removed.
- New project pop-up: the base path and a "Choose…" button share one line. Choose posts the pop-up to `POST /folders/pick`, which opens the system's own folder picker (`osascript` `choose folder` on macOS, `zenity` elsewhere; `src/web/folder_picker.rs`) at the typed path (nearest existing folder) or the home folder, and shows the pop-up again with the chosen folder (and its name, when none was typed); everything else typed is kept. Without a picker it falls back to the folder browser (`/folders`), whose "Use this folder" returns to the pop-up instead of creating the project directly.
- Project lists (org/board Info, homepage cards): the path sits on the name's line, and a path too long for the row loses its start (`…/projects/iter-webapp`, CSS right-to-left box with the path isolated inside; the full path is the tooltip). It shows only when its row is hovered or holds focus (always on touch screens); its space stays reserved so nothing moves.
- Filter bar (one component, `ui/filter_bar`, on every list with a search: tasks and projects): the syntax is a "?" beside Filter; hover shows it, a click keeps it shown until a click elsewhere (CSS `:focus-within`, no script). The tip hangs from the bar's right edge and grows to the left, at most the bar's width, so it never leaves the screen. The project search now has a syntax too. The bar is at most 40rem wide.
- Task search: an empty box means no filter (every task, done ones too). The links into a Tasks tab (the tab, breadcrumbs, back links) carry `q=is:open`, so a list still opens on the open tasks; a list with no `q` is unfiltered (the server reads an empty `q=` as none). Clear empties the search. A query with no `is:` term matches every status.
- `Config`, `TaskDefaults` and `Settings` derive `Serialize`.
- Agenda cards are shared with the Matrix: no tags, duration or time; priority edge with hidden text; fixed 15rem width, several per row; Schedule link hover-only on big screens; no underline.
- Agenda hides tasks scheduled after today.

### Fixed
