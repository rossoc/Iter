Basically I am integrating `https://github.com/rossoc/Iter` with llm-wiki.
Indeed, I want to use the `note` as the raw notes for the LLM-wiki of each
project, so that when a task is created, some context is added out of the box.
I am trying to develop an llm-wiki in the style of

```
https://github.com/tonbistudio/llm-wiki.git
```

Where the index.md is dropped and replace with a CLI implemented in Rust.
The markdown should be the source of truth, and it is used to build an RDF
graph. Basically there shouldn't be the need to have the graph/index, it can be 
built on the fly. In this way there is not way to diverge between graph and
notes. 

**Small ontology**

- **Classes:** `Page` with subtypes `Summary`, `Concept`, `Entity` and
  `Synthesis`. Plus `Journal` (a raw note), `Project`, `Task`, `Organization`.
- **Properties:**
  - Provenance: `derivedFrom` (page to `Journal`).
  - Structure: `mentions`, `partOf`, `relatedTo`.
  - Evidence: `supersedes`, `contradicts`.
  - Metadata: `confidence`, `tag`, `abstract`, `updated`.
- The one-line `abstract` per page is what makes cheap retrieval possible.

**LLM side: read as little as possible**
Retrieval in three levels, cheapest first:
1. `iter wiki find "<task text>" --budget 800` returns ranked page ids, each
   with its abstract and a short reason ("tag X, 1 hop from Y").
2. `iter wiki show <id> --level abstract|summary|full` loads one page at the
   depth you ask for.
3. `iter wiki neighbors <id> --hops 1` expands along typed edges.

Seeds come from task text, project and tags, with 1–2 hop expansion.
There are no embeddings at first.
The ranker is a small graph walk, so I'd check whether the rdf crate does more
than parse and serialize.
If you mean the small `rdf` crate, I'd compare it with `oxrdf` plus `oxttl`.
Neither has to do SPARQL here.

Other commands for the agent:
- `iter wiki schema` prints the instructions, which replace `CLAUDE.md` and are
  editable templates like the plan prompts.
- `iter wiki ingest [date]` runs the digest, using the same headless runner as
  `solve`.
- `iter wiki check` is the deterministic lint: orphans, dangling links, missing
  abstract, unknown relation types. The LLM-only lint covers contradictions.
- The agent edits wiki files directly, then runs `reindex` and `check`.
