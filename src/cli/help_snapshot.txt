===== iter
A command-line time tracker for projects and tasks, with tmux session and GitHub issue integration.

Usage: iter <COMMAND>

Commands:
  init          Create a project from the current directory (cwd becomes base_path)
  new           Create a project from scratch in a new folder
  clone         Create a project from a template project (copies its fields) or a git/GitHub repo (like `git clone`)
  tag           Manage tags: coloured labels shared by every task
  board         Manage boards: calendars that hold projects
  organization  Manage organizations: groups of projects that share defaults [alias: org]
  project       Manage projects; with no subcommand, lists every project by name
  task          Manage tasks; with no subcommand, lists every unfinished (queue or wip) task
  wiki          Read the wiki built from the notes: find the pages worth loading, follow their relations, query the graph, keep it consistent
  note          Notes: today's daily note (alone), daily notes, a task's notes and sketches, wiki pages
  session       Set up and track a task's session (tmux + git worktree/branch, and time spent)
  comment       Post a message as a comment on a task's linked GitHub issue
  t             Print `<project>/<task>` for the tmux session you're currently in
  help          Print this message or the help of the given subcommand(s)

Options:
  -h, --help
          Print help

  -V, --version
          Print version

===== iter organization info

Usage: iter organization info [OPTIONS] [NAME]

Arguments:

          Default: the organization of the tmux session's project

Options:

          A single day to report on, YYYY-MM-DD (default: today)

          - yaml:    The same report as plain YAML, for piping somewhere else
          - worklog: One line per task worked on in the period: `Completed <task>` when the task is done, `Worked on <task>` otherwise -- what is pushed to a time platform

          [default: text]

  -h, --help
          Print help (see a summary with '-h')

===== iter task
Manage tasks; with no subcommand, lists every unfinished (queue or wip) task

Usage: iter task [COMMAND]

Commands:
  new      Open a new task in nvim (optionally pre-filled from a GitHub issue); saving & quitting creates it
  edit     Edit an existing task in nvim; saving & quitting updates it
  delete   Delete a task (and its session-config and sessions)
  info     Name, description, and every session on a day or over an interval (default: today)
  list     List tasks, optionally filtered by project and/or status
  plan     The plan of a task: its goal, how, and a checklist with the state of every step. Alone it opens the plan in the editor
  prompt   Print the prompt that tells an agent what to do with a task, from one of the instructions: plan it, work through its plan, fix it...
  solve    Hand a task to an agent: it works on its own, headless, in the task's worktree, and leaves a log. Opens the editor first (agent, model, effort and the description it is given), unless --yes
  runs     The runs of a task, or the log of one
  done     Mark a task done: closes any open session, tears down its session-config (tmux session + worktree), and deletes that row
  pull     Bring the project's GitHub issues down as tasks: an issue nothing tracks becomes a new task, and a tracked one hands its open/closed state to the task's status
  push     Send the project's tasks up to GitHub: a task tracking no issue gets one opened for it, and a tracked issue is closed or reopened to match its task's status
  weekday  Average hours per weekday spent on a task
  help     Print this message or the help of the given subcommand(s)

Options:
  -h, --help
          Print help

===== iter task solve
Hand a task to an agent: it works on its own, headless, in the task's worktree, and leaves a log. Opens the editor first (agent, model, effort and the description it is given), unless --yes

Usage: iter task solve [OPTIONS] --instruction <INSTRUCTION> [TASK] [-- <EXTRA>...]

Arguments:
  [TASK]
          `<project>/<task>` (default: the task of the tmux session you're in)

  [EXTRA]...
          Passed to the harness as they are, after `--`

Options:
  -i, --instruction <INSTRUCTION>
          The instruction the agent follows: `instructions/<name>.md` in the task's folder, the project's or organization's notes, or iter's config folder (nearest first)

      --agent <AGENT>
          The harness that runs the agent

          [possible values: claude]

      --model <MODEL>


      --effort <EFFORT>
          low, medium or high

  -y, --yes
          Skip the editor

      --wait
          Stay until the agent has finished instead of leaving it running

      --subagent
          For a subagent of the session you are in: start nothing, record the run and print its prompt. Close it with `iter task runs --close <n>` when the subagent is done. `--model` and `--effort` record what the subagent is started with (default: inherit)

  -h, --help
          Print help

===== iter wiki
Read the wiki built from the notes: find the pages worth loading, follow their relations, query the graph, keep it consistent

Usage: iter wiki <COMMAND>

Commands:
  find           Rank pages by how well their path, title, tags and description match the words, best first, until the token budget is spent
  grep           Search the text of the pages for a regular expression
  show           One page: `<path>` in the level you ask from, `<level>:<path>` in another
  neighbors      The pages within a few relations of one, nearest first
  check          Lint the wiki: dangling links, missing descriptions and tags, broken front matter, relations the ontology does not allow, and what to do next. Fails if there are errors
  mv             Move a page inside its level, rewriting every reference to it. Only the levels in scope are rewritten: references from other tasks' folders or from an organization's projects are not (run `check` there)
  sparql         Run a SPARQL query over the graph (`iter:`, `owl:`, `rdf:`, `rdfs:`, `xsd:` are declared). Reads only
  export         The whole graph as N-Triples, with what the ontology derives
  schema         The instructions for an agent working with the wiki, filled in from the ontology
  ingest         Have an agent turn the notes that changed (or were never ingested) into pages. Its changes are left uncommitted, to be reviewed with `pending`. Needs the notes folder to be in a git repository
  build-concept  Have an agent write a concept that includes the given ideas
  pending        What the agents changed in the wiki and nobody has accepted yet
  help           Print this message or the help of the given subcommand(s)

Options:
  -h, --help
          Print help
